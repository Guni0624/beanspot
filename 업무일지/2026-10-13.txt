4. 문제와 해결 과정

   ■ 17시 할 일 알림이 오지 않음
     - 문제: 평일 17시에 와야 할 "오늘 할 일" 카톡이 오지 않음.
     - 궁금했던 점: 컴퓨터가 꺼져 있어서 그런가?
       → 아님. 이 알림은 내 PC가 아니라 GitHub 서버의 컴퓨터
         (runs-on: ubuntu-latest)에서 실행됨.
         카카오 토큰은 GitHub Secrets에, 할 일은 GitHub에 올라간
         업무일지에서 읽으므로 내 PC는 전혀 필요 없음.
     - 원인(추정):
         (1) 정각 예약은 GitHub 쪽 부하로 지연·누락되기 쉬움
         (2) 워크플로를 만든 직후에는 첫 예약 실행이 빠지는 경우가 많음
         GitHub가 이유를 알려주지 않아서 둘 중 무엇인지 확정은 못 함.
     - 해결: 예약 시각을 17:04로 옮김. 내일 실제 수신 여부로 최종 확인.
     - 확인 못 한 것: 예약 실행은 미리 테스트할 수 없어서
       내일 17:04 이후에야 결과를 알 수 있음.

5. 오늘 배운 개념 (용어 정리)
   - schedule 이벤트: cron 시간에 GitHub가 자동으로 실행하는 방식.
     "최선을 다해 실행"이라 정확한 시각이나 실행 자체를 보장하지 않음.
   - workflow_dispatch 이벤트: 사람이 직접(수동) 실행하는 방식.
   - gh run list 의 event 칸: schedule(예약) / workflow_dispatch(수동)
     / push(업로드로 실행) 중 무엇으로 실행됐는지 알려줌.
     → 오늘은 schedule 기록이 아예 없어서 "예약이 안 돌았다"고 판단.
   - 러너(runner): 워크플로를 실제로 실행하는 GitHub 서버의 컴퓨터.
     그래서 내 PC 전원과 무관.
   - 주의: 일지는 반드시 push까지 해야 함. PC에만 저장하면 GitHub는
     예전 일지의 [내일 할 일]을 보냄.

6. 자주 쓸 명령어
   - gh run list                                    전체 실행 기록
   - gh run list --workflow daily-todo.yml          할 일 알림 기록만
   - gh workflow list                               워크플로 켜짐/꺼짐 상태
