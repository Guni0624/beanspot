2. 수정한 파일 상세

   ■ app.js — 버그 1: 평점 재계산 오류
     - 무엇을: 리뷰 작성 후 평균 평점 계산 방식
     - 왜: 카페 데이터는 "리뷰 128개, 평점 4.8"인데 실제 저장된 리뷰
           본문은 샘플 2개뿐. 기존 코드는 이 2~3개로만 평균을 내서
           1점 리뷰 하나에 4.8 → 3.3으로 폭락.
     - 어떻게: "누적 평균" 공식으로 변경
           새 평점 = (기존 평점 × 기존 리뷰 수 + 새 별점) ÷ (리뷰 수 + 1)
           const totalStars = currentCafe.rating * currentCafe.reviewCount + selectedRating;
           currentCafe.reviewCount += 1;
           currentCafe.rating = parseFloat((totalStars / currentCafe.reviewCount).toFixed(1));
     - 결과: 4.8 → 4.8 유지 (129개 중 1개만큼만 반영)

   ■ app.js — 버그 2: 태그 누르면 검색이 풀림
     - 왜: 검색은 "이미 그려진 핀을 숨기는" 방식, 태그 필터는
           "핀을 전부 다시 그리는" 방식이라 서로 덮어씀.
     - 어떻게: 검색어를 searchQuery 변수(상태)에 저장하고,
           핀을 그리는 renderPins() 한 곳에서 커피태그·목적태그·검색어
           세 조건을 모두 적용. → 따로 있던 filterPinsByName() 삭제.
     - 배운 점: 화면을 바꾸는 경로가 여러 개면 서로 충돌한다.
           "상태(state)는 한 곳에, 그리기는 한 함수에서"가 원칙.

   ■ app.js — 버그 3: XSS(HTML 삽입) 보안 문제
     - 왜: 리뷰·공지 글을 innerHTML로 넣어서, 글에
           <img src=x onerror=alert(1)> 를 쓰면 그 코드가 실행됨.
           서버가 붙으면 다른 사용자 브라우저에서 악성코드 실행 가능.
     - 어떻게: escapeHtml() 함수 추가. < > & " ' 를 &lt; 등
           안전한 글자로 바꾼 뒤 화면에 넣음.
           리뷰 작성자/날짜/본문/태그/사장님 답글/공지/카페 이름에 적용.

   ■ app.js — 버그 4: 별점을 아예 누를 수 없음 (실행 테스트로 발견!)
     - 증상: 별을 눌러도 선택 안 됨 → "별점을 선택해주세요!"만 뜸
             → 리뷰를 한 번도 등록할 수 없는 상태였음.
     - 원인: 순서 문제.
             ① 코드가 별 아이콘 <i>에 클릭 이벤트를 연결
             ② 그 다음 아이콘 라이브러리(lucide)가 <i>를 <svg>로 "교체"
             → 교체되면서 연결해 둔 클릭 이벤트가 사라짐
     - 해결: "이벤트 위임(event delegation)"
             별 5개를 감싸는 부모 상자(#rating-selector)에 클릭을 연결하고,
             클릭된 대상이 어떤 별인지 e.target.closest(".write-star")로 찾음.
             부모 상자는 교체되지 않으니 이벤트가 유지됨.
     - 교훈: 이전 수정 때 "문법 검사"만 하고 실제 실행을 안 해서 놓침.
             → 그래서 "직접 실행해서 검증" 규칙을 만들게 됨.

   ■ app.js — 버그 5: 뒤로가기가 항상 지도로 감
     - 해결: detailReturnScreen 변수에 "상세 화면을 열기 직전 탭"을
             기억했다가 뒤로가기 때 그 화면으로 복귀.

   ■ .gitignore

4. 문제와 해결 과정

   ■ 카카오 연결 실패 3번
     ① 실패: "메시지 동의가 빠짐 (받은 권한: undefined)"
        원인: 내 스크립트 버그. 카카오 응답에 권한 목록이 없을 때도 있는데
              무조건 실패 처리함.
        해결: 목록 대신 "실제로 메시지를 보내보고" 판단하도록 변경.
     ② 실패: 카카오 오류 -501 "카카오톡 사용자가 아님"
        원인: 개발자 앱 만들 때 쓴 이메일 계정(카톡과 연결 안 된 계정)으로
              로그인됨.
        해결: 로그인 화면이 항상 뜨게(prompt=login) 바꾸고, 카톡에 연결된
              계정으로 로그인. (개발자 계정과 알림 받는 계정은 달라도 됨)
     ③ 실패: 오류 -402 "권한 없음"
        원인: 카카오에 직접 조회(/v2/user/scopes) → 앱 설정은 정상,
              사용자가 "카카오톡 메시지 전송" 체크를 안 한 상태(agreed:false)
        해결: 동의 화면에서 체크 후 성공.

   ■ gh 명령어 "인식되지 않음"
     - 원인: VS Code는 시작할 때 PATH(프로그램 위치 목록)를 한 번만 읽음.
             gh는 그 뒤에 설치됨.
     - 해결: 전체 경로로 실행 & "C:\Program Files\GitHub CLI\gh.exe" ...
             또는 VS Code 재시작.

   ■ .env에 GitHub 토큰 앞 "GH_PAT=" 누락
     - 값만 붙여넣어서 프로그램이 이름을 못 찾음 → 앞에 GH_PAT= 추가.

5. 오늘 배운 개념 (용어 정리)
   - git: 파일 변경 이력을 저장하는 도구. 커밋 = 저장 시점 스냅샷.
   - push: 내 PC의 커밋을 GitHub 서버로 올리기 (= 백업)
   - 태그(tag): 특정 커밋에 붙이는 이름표. prototype-v0 = 수정 전 원본
   - XSS: 사용자 입력에 섞인 코드가 다른 사람 브라우저에서 실행되는 공격
   - 이벤트 위임: 자식 대신 부모에 이벤트를 걸어 자식이 바뀌어도 동작 유지
   - localStorage: 브라우저 안에만 저장되는 작은 저장소 (서버 아님)
   - E2E 테스트: 실제 사용자처럼 처음부터 끝까지 조작해 보는 테스트
   - headless 브라우저: 화면 없이 백그라운드로 돌아가는 브라우저
   - API 키 / 토큰: 프로그램이 서비스에 "나 맞아요"를 증명하는 비밀번호
   - OAuth: 비밀번호를 앱에 주지 않고 "동의"만으로 권한을 주는 로그인 방식
   - access token / refresh token: 짧게 쓰는 출입증 / 출입증 재발급용 열쇠
   - 리다이렉트 URI: 로그인 후 카카오가 결과를 돌려보낼 주소
   - .env: 비밀키를 코드와 분리해 보관하는 파일 (git에 안 올림)
   - GitHub Actions: GitHub 서버가 정해진 때 대신 프로그램을 실행해 줌
   - cron: 실행 시간 표기법. "분 시 일 월 요일" (0 8 * * 1-5)
   - UTC: 세계 표준시. 한국(KST) = UTC + 9시간
   - GitHub Secrets: 비밀키를 GitHub에 암호화해 보관하는 곳
   - PAT(개인 액세스 토큰): 프로그램이 내 GitHub 계정 일부 권한을 쓰는 열쇠
   - PATH: 명령어를 입력했을 때 프로그램을 찾는 폴더 목록
